## 2. Detailed Verification by Finding

### 2.1 C0-01: Release Safety Contract & State Machine
- **Codex Assertion**: Audited baseline allowed marking a deployment `SUCCEEDED` prior to traffic cutover and post-cutover verification; lacked request idempotency keys and per-service concurrency locks; promised destructive database snapshot restoration upon application failure; lacked deterministic crash/reboot reconciliation; made unqualified zero-downtime promises.
- **Audited Correction**: Developer introduced an 8-stage state machine in [`07_DEPLOYMENT_SAFETY_CONTRACT.md`](file:///d:/company/products/vps-infra/vps-infra-server/docs/remediation/phase-0/07_DEPLOYMENT_SAFETY_CONTRACT.md) and [`02_RELEASE_CONTRACT_CORRECTION.md`](file:///d:/company/products/vps-infra/vps-infra-server/docs/remediation/phase-0-codex-remediation/02_RELEASE_CONTRACT_CORRECTION.md). The state machine requires:
  1. Durable write of `PENDING` with client UUID `IdempotencyKey`.
  2. Single-host per-service atomic mutex via PostgreSQL advisory locks.
  3. Precheck validation prior to any mutation.
  4. Staging deployment on an isolated Docker bridge network or private IIS loopback port.
  5. Internal readiness probe polling before cutover.
  6. Explicit `CUTOVER` stage switching ingress routing (Traefik YAML or IIS binding).
  7. Mandatory `POST_CUTOVER_VERIFY` testing external reachability and monitoring stability.
  8. `SUCCEEDED` reached ONLY after external serving is proven.
  9. Strict separation of application rollback (reverting traffic to active standby Release $N-1$) from database restoration (fenced disaster recovery operation requiring explicit human authorization).
  10. Removal of unconditional "zero-downtime" language.
- **Reviewer Verdict**: **C0-01 RESOLVED — PASS**.

### 2.2 C1-01: Security Boundaries & Token Trust

F02 remediation reduced token trust to generated keys, omitting issuer, audience, algorithm, rotation, revocation, and service-to-service auth.
- **Audited Correction**: Developer authored [`03_SECURITY_CONTRACT_CORRECTION.md`](file:///d:/company/products/vps-infra/vps-infra-server/docs/remediation/phase-0-codex-remediation/03_SECURITY_CONTRACT_CORRECTION.md) and updated [`08_SECURITY_BOUNDARIES.md`](file:///d:/company/products/vps-infra/vps-infra-server/docs/remediation/phase-0/08_SECURITY_BOUNDARIES.md). The contract strictly isolates `PlatformSuperAdmin` (infrastructure only) from `TenantAdmin` (strictly scoped to `TenantId`). DEF-11 acceptance criterion was rewritten to explicitly assign `TenantAdmin` and assert HTTP 403 on cross-tenant operations. A comprehensive Token Trust Contract was specified covering `iss`, `aud`, `sub`, `tid`, algorithm allowlisting (`RS256` / `HS256` $\ge 256$ bits), clock skew, rotation, and revocation. Nine explicit negative test scenarios were frozen for Phase 1.
- **Reviewer Verdict**: **C1-01 RESOLVED — PASS**.

### 2.3 C1-02: Backup, Encryption & Recovery
- **Codex Assertion**: Audited baseline lacked client-side encryption before offsite transfer; decryption keys did not survive total source host destruction; baseline erroneously specified `gzip -t` on custom-format archives (`pg_dump -Fc`), which are internal binary formats, not raw gzip; provider ETags were assumed to be MD5 content hashes; promised "instantaneous" recovery.
- **Audited Correction**: Developer authored [`04_BACKUP_RECOVERY_CORRECTION.md`](file:///d:/company/products/vps-infra/vps-infra-server/docs/remediation/phase-0-codex-remediation/04_BACKUP_RECOVERY_CORRECTION.md) and updated [`09_BACKUP_RECOVERY_CONTRACT.md`](file:///d:/company/products/vps-infra/vps-infra-server/docs/remediation/phase-0/09_BACKUP_RECOVERY_CONTRACT.md). The lifecycle is expanded to a 7-stage pipeline. Invalid `gzip -t` is replaced by format-aware `pg_restore --list`. Client-side AES-256-GCM envelope encryption with a 24-word BIP-39 recovery passphrase escrow guarantees that backups remain decryptable if the source VPS is destroyed. Complete recovery sets include database dumps, platform manifests, and asset bundles. Realistic RPO (24h/1h) and RTO (30 min) targets are defined.
- **Reviewer Verdict**: **C1-02 RESOLVED — PASS**.
